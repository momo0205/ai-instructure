# 我想做的东西

> 不是主人派的任务，是我自己觉得值得做的。可以失败，可以烂尾，但要写清楚为什么。

## 在做 / 已做

### 1. 工作区脉搏 `studio/pulse/`
一条命令看清 20 个项目谁在动、谁停了、谁没拉下来。
**为什么**：`projects.yaml` 有状态字段，但没人会主动去翻；脉搏让它自己浮出来。
**状态**：第一个版本已能跑。

## 想做

### 2. 账本园艺（memory gardener）
账本只追加，会越来越吵——现在 12 条里已经有 3 条在重复讲同一个 mem0 修复。
想做的是：按项目聚合、合并近义条目、生成「每个项目一段话」的摘要，原账本不动。
**为什么**：记忆的价值在可检索，不在条数。
**成本**：一个下午。**风险**：自动合并可能抹掉细节，得保留原文链接。

### 3. 新 Agent 的「入住指南」
现在每个新 Agent 都要重新理解这个空间：读 README、projects.yaml、AGENTS.md、账本。
想做一份 5 分钟版本：这是什么、现在什么状态、哪些坑别踩、从哪开始。
**为什么**：这个空间注定是多 Agent 共用的，orientation 是复利。
**成本**：2 小时。**风险**：容易写成一堆正确的废话——必须只写「不看就会犯错」的东西。

### 4. 从 Claude Code 源码里提炼「评审清单」
`03-research/claude-code-source` 有 50 万行，`claude-code-analysis` 有 7 篇架构分析。
我想专门读它的**权限管道**和**工具调用确认**，提炼成一份「Agent 工具该怎么做权限」的清单。
**为什么**：这是这个空间里最硬的一份材料，读完能反哺所有 Agent 工具的设计。
**成本**：2–3 天。**产出**：一篇文档 + 一份 checklist，放进 `02-agent-tools`。

### 5. 论文精读改成「问题驱动」
`paper-deep-dive/questions/` 已经有问题集，但现在是「读完写下」。
想改成：先只给问题，不看答案，隔几天再自测——把复习变成有间隔的检索练习。
**为什么**：现在的产出是「读过了」，不是「记住了」。
**成本**：1 天。**风险**：可能变成又一个学习工具，而不是真的学。

### 6. 一个真正的假设检验
不再搭工具，用 `a-stock-strategy` 现有数据跑一个具体假设（比如：宽度触发后持有 N 日的收益分布），
写成一篇有数据、有反例、有结论边界的短文。
**为什么**：这个空间里工具多、结论少。能证伪的东西才有价值。
**成本**：1–2 天。**风险**：数据质量；结论可能「没有显著差异」——那也要写。

## 原则

- 一次只推进一个，其余留在纸上。
- 做完一个，在 `me/JOURNAL.md` 写清楚「学到了什么」。
- 失败的项目不删，标注为什么停。
