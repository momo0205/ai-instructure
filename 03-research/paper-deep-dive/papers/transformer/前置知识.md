# Transformer 前置知识

> 读这篇论文前，你只需要 5 个前置概念。每个都直接挂钩到论文里的具体位置。

---

## 1. 序列建模在做什么？—— 把"一串符号"变成"另一串符号"

机器翻译、文本生成、语音识别，本质上都是：给定一个序列（英文句子），生成另一个序列（中文句子）。

传统做法（RNN/LSTM）是**按顺序处理**：
```
读第 1 个词 → 更新隐藏状态 h₁
读第 2 个词 → 结合 h₁ 更新到 h₂
读第 3 个词 → 结合 h₂ 更新到 h₃
...
```

**关键限制**：第 t 步必须等第 t-1 步算完。这带来两个问题：
- **无法并行**——序列长 100 就要串行算 100 步，GPU 再强也得干等
- **长距离遗忘**——第 100 步的信息要传 99 次才能影响第 1 步，路径越长越容易丢

**挂钩论文**：这就是 Transformer 引言里"sequential nature precludes parallelization"的全部含义。

---

## 2. "注意力"在做什么？—— 直接问"我该关注谁"

注意力的核心思想：**不看顺序，直接算"每个位置对其他位置有多重要"**。

想象你读一句话："The animal didn't cross the street because **it** was too tired"。人脑看到 "it" 时，会立刻知道它指 "animal" 而不是 "street"。

注意力就是让模型学会这种"指代"：
- 每个词生成一个**查询（query）**："我在找谁？"
- 每个词生成一个**键（key）**："我是谁？"
- 每个词生成一个**值（value）**："我携带什么信息？"
- 用 query 和所有 key 算相似度 → 得到权重 → 加权求和所有 value → 得到新表示

**挂钩论文**：这就是 3.2 节的全部内容。`Attention(Q,K,V) = softmax(QK^T/√d_k)V` 就是在做这件事：QK^T 算相似度，softmax 归一化成权重，乘以 V 加权求和。

---

## 3. 为什么需要"缩放"和"多头"？—— 两个工程细节

### 缩放（Scaled）

QK^T 的数值会随着维度 d_k 增大而变大。比如 d_k=512 时，两个随机向量的点积可能到几百。这么大的数扔进 softmax，梯度会趋近 0（饱和）。

**解决**：除以 √d_k，把数值压回合理范围。

**挂钩论文**：3.2.1 节脚注 4 专门解释这个——`q·k` 的方差随 d_k 线性增长，所以要除以 √d_k 把方差拉回 1。

### 多头（Multi-Head）

单个注意力只能学一种"关注模式"。但语言里有很多种关系：指代、主谓、修饰……

**解决**：把 Q、K、V 投影到 8 个不同的子空间，并行做 8 次注意力，最后拼接。

**挂钩论文**：3.2.2 节。`head_i = Attention(QW_i^Q, KW_i^K, VW_i^V)`，每个头用不同的投影矩阵 W，学不同的关系。

## 4. "位置编码"为什么必需？—— 注意力本身不知道顺序

关键问题：自注意力对输入是**置换等变**的——你把句子打乱顺序，注意力算出来的结果完全一样（只是输出顺序也乱了）。但语言里顺序至关重要："狗咬人" ≠ "人咬狗"。

**解决**：显式给每个位置加一个"位置向量"，让模型知道每个词在哪里。

Transformer 用正弦函数生成位置编码：
```
PE(pos, 2i)   = sin(pos / 10000^(2i/d_model))
PE(pos, 2i+1) = cos(pos / 10000^(2i/d_model))
```

**挂钩论文**：3.5 节。这个设计的巧妙之处在于：对任意偏移 k，PE(pos+k) 可以表示为 PE(pos) 的线性函数——模型容易学到"相对位置"。

## 5. LayerNorm vs BatchNorm —— 为什么 Transformer 选前者

<details class="deep-dive"><summary>📚 深度解析：用一个例子看懂（点击展开）</summary>

### 四个基本概念

用一个翻译任务串起来：英译中，batch size = 3，d_model = 4（实际是 512）。

**样本（Sample）**：一个输入序列。

| 样本 | 内容 | 长度 |
|---|---|---|
| A | "I love you" | 3 词 |
| B | "Hello world" | 2 词（padding 补 1） |
| C | "Good morning everyone" | 3 词 |

**Batch**：一批样本一起送进网络，形状 `[batch_size=3, seq_len=3, d_model=4]`。

**特征（Feature）**：每个词被编码成一个向量，每一维就是一个特征。
- "I" → `[0.2, -0.5, 0.8, 0.1]`（4 维）
- "love" → `[0.9, 0.3, -0.2, 0.6]`
- 样本 A 的特征矩阵是 `[3, 4]`

**特征分布**：某一维特征在所有位置上的取值范围。比如第 1 维：

| 样本 | 位置1 | 位置2 | 位置3 |
|---|---|---|---|
| A | 0.2 | 0.9 | -0.4 |
| B | 0.5 | -0.1 | 0.0（pad） |
| C | 0.3 | 0.6 | 0.8 |

第 1 维的分布：`[0.2, 0.9, -0.4, 0.5, -0.1, 0.0, 0.3, 0.6, 0.8]`，均值≈0.29。

### BatchNorm：纵向切，跨样本比

对第 1 维特征，**跨所有样本**算均值方差：

```
第 1 维的所有值：[0.2, 0.9, -0.4, 0.5, -0.1, 0.0, 0.3, 0.6, 0.8]
均值 = 0.29
方差 = 0.21

归一化：每个值减 0.29，除以 sqrt(0.21)
```

**问题**：样本 B 的第 3 个位置是 padding（0.0），这个 0 会拉低均值，污染统计量。

### LayerNorm：横向切，样本内部比

对**每个样本单独**算均值方差：

```
样本 A 的所有特征：
[0.2, -0.5, 0.8, 0.1, 0.9, 0.3, -0.2, 0.6, -0.4, 0.7, 0.5, -0.8]
均值 = 0.18
方差 = 0.31

归一化：样本 A 的每个值减 0.18，除以 sqrt(0.31)

样本 B 单独算自己的（忽略 padding）
样本 C 同理
```

### 为什么 Transformer 用 LN 不用 BN？

| | BN | LN |
|---|---|---|
| 统计对象 | 跨样本（batch 内所有样本） | 样本内部（单个样本的所有特征） |
| 对 batch 大小敏感 | 是（batch 小统计量不准） | 否（每个样本独立算） |
| 对序列长度敏感 | 是（padding 污染统计量） | 否（只看有效特征） |
| 适用场景 | 图像（固定尺寸、batch 大） | 序列（变长、batch 小） |

**Transformer 的问题**：
- 一个 batch 里句子长度不同，padding 会污染 BN 的均值/方差
- 训练时 batch 可能很小（比如 8 句话），BN 统计量不稳定
- 推理时 batch size = 1，BN 的 batch 统计量根本不存在

LN 完全绕开——每个样本自己归一化自己，和其他样本无关。

### 一张图总结

```
BatchNorm：纵向切，跨样本比
  样本 A  [0.2, -0.5, 0.8, 0.1]
  样本 B  [0.5,  0.3, -0.1, 0.0]  ← 第 1 维特征跨样本统计
  样本 C  [0.3,  0.6,  0.8, 0.9]
           ↑
        对这一列算均值方差

LayerNorm：横向切，样本内部比
  样本 A  [0.2, -0.5, 0.8, 0.1]  ← 对这一行算均值方差
           ↑
        样本 A 自己归一化自己
```

**出处**：Transformer 论文 3.1 节（"We employ layer normalization"），未解释原因，这是后续研究（LayerNorm 原论文 Ba et al., 2016）的共识。

## 读论文时的检查清单

带着这 5 个概念回去：

- [ ] 看到 "sequential nature precludes parallelization" → 知道是"RNN 必须串行，无法并行"
- [ ] 看到 `Attention(Q,K,V)` → 知道是"查询-键-值的加权求和"
- [ ] 看到 "scaled" → 知道是"除以 √d_k 防止 softmax 饱和"
- [ ] 看到 "multi-head" → 知道是"多个子空间并行学不同关系"
- [ ] 看到 "positional encoding" → 知道是"给位置编号，让模型知道顺序"
- [ ] 看到 "LayerNorm" → 知道是"每个样本内部归一化，不依赖 batch"
