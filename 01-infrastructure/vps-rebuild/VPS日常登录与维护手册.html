01

日常操作速查

登录：在 Mac 执行一条命令

打开 Mac 的“终端”，在类似 (base) ➜ ~ 的本地提示符后执行：

Mac 本地终端 · 日常登录 / 重启后重连
ssh -i "$HOME/.ssh/ironmao_vps" -o IdentitiesOnly=yes deployer@23.94.184.3

看到 deployer@obvymadx:~$ 表示已进入服务器。若私钥口令为空，通常直接登录；有口令时输入 Mac 私钥口令。执行 whoami 应输出 deployer。

教程第 6 步执行后，root 直接 SSH 登录关闭，日常使用上面的 deployer 命令。私钥保留在 Mac，不上传到服务器。

可选：设置简称，以后只输入 ssh ironmao-vps

在 Mac 本地编辑 SSH 配置：

Mac 本地终端 · 编辑已有文件，保留其他配置
nano "$HOME/.ssh/config"

在文件顶部添加下面的配置；若已有同名 Host ironmao-vps，修改那一段，不重复添加。不清空其他 Host 配置。

文件内容 · SSH config · 粘贴到 nano，不是终端命令
Host ironmao-vps
  HostName 23.94.184.3
  User deployer
  Port 22
  IdentityFile ~/.ssh/ironmao_vps
  IdentitiesOnly yes
  ServerAliveInterval 30

按 Control + O、回车保存，Control + X 退出。在 Mac 执行：

Mac 本地终端 · 保存配置后
chmod 600 "$HOME/.ssh/config"
ssh ironmao-vps

简称只是把上述连接参数保存在 Mac；以后 IP 或用户名改变，需要同步修改这段配置。旧的 ironmao 简称可能指向工作区另一台服务器，本手册使用独立的 ironmao-vps。

管理权限：sudo 和 root 环境

关闭 root SSH 登录，是限制直接从网络以 root 登录；root 账号仍然存在。普通操作用 deployer，管理系统时用 sudo：

服务器终端 · deployer · 查看 SSH 服务
sudo systemctl status ssh --no-pager

需要输入时，sudo 询问的是 deployer 的密码。需要连续执行管理员操作时：

服务器终端 · deployer · 进入 root 环境
sudo -i

提示符变成 root@obvymadx:~# 后，当前拥有 root 权限，$HOME 也变成 /root。完成管理员操作后：

服务器终端 · root 环境 · 返回 deployer
exit

这次 exit 返回 deployer；在 deployer 的 SSH 会话里再执行 exit，才退出服务器、回到 Mac。安装服务或改系统配置可用 sudo / sudo -i，网站构建与 SCP 上传仍从 Mac 本地执行。

看到的提示输入什么
Enter passphrase for key ...Mac 私钥口令；空口令时通常不询问
[sudo] password for deployer:创建 deployer 时设置的密码
VNC 中 root 的 Password:服务器最新 root 密码

这些值保存在自己的密码管理工具，不写进手册或命令参数。

04

日常操作速查

打开 3X-UI 管理面板

安装时选择 Bind the panel to 127.0.0.1 only? → y，管理面板只接受服务器本机访问。Mac 通过 SSH 隧道连接，节点仍使用公网 8443。

在 Mac 新开一个本地终端窗口，执行并保持运行：

Mac 本地终端 · 隧道窗口 · 3X-UI 安装后
ssh -i "$HOME/.ssh/ironmao_vps" -o IdentitiesOnly=yes -N -L 127.0.0.1:18080:127.0.0.1:18080 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 deployer@23.94.184.3

连接后通常没有提示符，是正常现象。在浏览器打开 http://127.0.0.1:18080/安装输出的WebBasePath/，把路径换成本次安装时保存的真实值。用户名、密码使用 3X-UI 自己的登录信息。

面板登录信息在安装日志的 Panel Installation Complete! 区域，后面的 Fail2ban 日志可能把它顶到上方。若已找不到输出，在服务器自己的终端查看初始记录：

服务器终端 · deployer · 凭据只在自己电脑查看
sudo grep -E '^XUI_(USERNAME|PASSWORD|WEB_BASE_PATH)=' /etc/x-ui/install-result.env

之后已更换的密码或路径使用最新值；保存到自己的密码管理工具，不把输出发到聊天。完整说明见 主教程第 7 步。

不使用 http://23.94.184.3:18080 访问面板。需要准确的可点击地址，可在 完整教程第 8 步填写顶部 WebBasePath 参数后打开。

提示 Address already in use：改用本地 28080

Mac 的 18080 已被占用时，复制下面的备用命令。服务器面板仍是 18080，只把 Mac 的入口改为 28080：

Mac 本地终端 · 28080 备用隧道 · 保持窗口运行
ssh -i "$HOME/.ssh/ironmao_vps" -o IdentitiesOnly=yes -N -L 127.0.0.1:28080:127.0.0.1:18080 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 deployer@23.94.184.3

浏览器改用 http://127.0.0.1:28080/安装输出的WebBasePath/，把路径换成实际值，末尾保留 /。完整教程的默认打开按钮仍指向 18080，使用备用隧道时应输入这个 28080 地址。

使用完毕，在隧道窗口按 Control + C 关闭。浏览器面板连接结束，服务器的代理节点仍运行。

FlClash 更新订阅时，另按 主教程第 10 步开启 Mac 28081 → VPS 2096 的订阅隧道。现有面板隧道只转发 18080；订阅 URL 的回环地址与 YAML 内节点的公网 IP 分别用于下载和代理连接。更新完成可关闭订阅隧道，已载入节点继续使用。

完成网站部署后，可以查看金融站当前发布目录：

服务器终端 · 金融站部署后 · 只读查看版本
readlink -f /srv/www/finance/current
ls -1 /srv/www/finance/releases

仅更新静态文件时按发布流程切换版本。修改 Caddy 配置时先验证，再 reload：

服务器终端 · deployer · 修改并保存 Caddyfile 后先检查
sudo caddy validate --config /etc/caddy/Caddyfile --adapter caddyfile

只有显示配置有效、命令正常结束后，才执行：

服务器终端 · Caddy 配置验证成功后
sudo systemctl reload caddy

发布失败时保留 current 指向原版本。需要回滚时，在 第 18 步回滚命令中填入实际存在、验证过的旧版本目录。Caddy 和发布的完整命令保持在主教程里，避免两份流程分别维护后产生差异。

更新、重启和重新连接

系统更新在服务器执行，先确保近期备份可用：

服务器终端 · deployer · 逐条完成
sudo apt update
sudo apt upgrade

出现 System restart required 时，需要安排一次重启。首次重建时先完成第 6 步的新 SSH 连接与 sudo 验证；日常维护时确认没有正在执行的发布或备份，准备好重连命令后执行：

服务器终端 · deployer · 准备短暂停机时
sudo reboot

SSH 自动断开。等待 VPS 恢复 Running，回到 Mac 本地或新开终端，再用第 1 节的登录命令；已配置简称时可用 ssh ironmao-vps。重连后执行：

重新连接后的服务器终端 · deployer
whoami
sudo -v
sudo systemctl is-active ssh

代理和网站完成安装后，再检查 x-ui、caddy 与实际节点 / 网站可用性。普通重启无需重新生成私钥；若主机指纹变化，按完整教程第 4 步通过 VNC 核对。

只重启代理服务或重新加载网站服务

确认相应服务已安装后，按需要选一条：

服务器终端 · 重启已安装的 3X-UI，会短暂影响代理
sudo systemctl restart x-ui
服务器终端 · Caddy 配置验证成功后重新加载
sudo systemctl reload caddy

备份、回滚与维护记录

修改节点、网站或升级服务前，使用 完整教程第 18 步的备份命令。代理数据库用 SQLite backup，网站配置与发布目录打包，最后下载到 Mac 并检查归档可读。

  • 服务器备份：/var/backups/ironmao；下载到 Mac 的最新包：~/Desktop/ironmao-latest.tar.gz。
  • 网站回滚：切回已经验证的旧 releases 目录；保留多个版本，故障时不用重新搭整台服务器。
  • 月度查看 ColoCrossing 续费 / 流量，检查系统更新、磁盘空间和服务状态。
  • 3X-UI 更新前先备份，查看官方版本说明，再按第 18 步管理菜单操作。

下次维护时说明“改了什么、哪一步、验证结果”，可继续更新这份工作区手册。它是操作参考，不会自动监控服务器或记录每次实际部署。

无法登录或服务异常时

现象先做什么
关闭 root SSH 后，ssh root@... 被拒绝使用第 1 节的 deployer + 私钥命令；需要 root 环境时 sudo -i
Permission denied (publickey)核对用户名 deployer、Mac 私钥路径和完整教程第 5 步的授权文件；保持仍能用的旧连接
Too many authentication failures使用本手册带 IdentitiesOnly=yes 的命令，检查 Mac 是否还有其他匹配的 IdentityFile 配置
Connection refused / 超时检查 VPS Running、IP、云防火墙 22；从 VNC 查看 SSH 与 UFW
REMOTE HOST IDENTIFICATION HAS CHANGED按完整教程第 4 步核对同类型主机指纹，一致后才移除旧记录；不关闭主机密钥检查
管理面板打不开确认隧道窗口仍运行、路径正确、x-ui active；面板不会直接在公网 18080 打开
Mac 启动时 OpenClaw 补全文件不存在这是 Mac 的 shell 配置提示；本轮后续 SSH 登录已成功，修复本地配置可另行处理

打开 本 VPS 的干净产品详情页 → 管理区域顶部 VNC 图标 → Launch HTML 5 VNC Client。VNC 可用 root 和服务器密码登录，SSH 的 PermitRootLogin 设置不会禁止这个控制台入口。

ColoCrossing 网页 VNC · root · 只读排查 SSH 与防火墙
systemctl status ssh --no-pager
ss -lntp
ufw status verbose

先收集状态，不直接关闭防火墙或改认证配置。VNC 也无法打开时，用 已登录的商家工单请求恢复控制台 / 提供管理链接。故障细节参见 主教程故障表。
