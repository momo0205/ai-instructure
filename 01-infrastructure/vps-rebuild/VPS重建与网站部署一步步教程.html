03

浏览器 · 这是清空系统盘的一步

登录 ColoCrossing，重装系统

无需旧系统的登录密码，只需要能够登录购买 VPS 的商家账号。Reboot 是重启，Reinstall OS 才是重装。本次应进入服务器管理区域的 Install，而不是左侧 Reboot VPS。

  1. 打开 这台 VPS 的产品详情页 ↗，如需登录，使用购买服务器的 ColoCrossing 账号。这个服务编号来自本次实际页面；核对页面 IP 与顶部参数一致，换服务器时从 Services 重新选择对应产品。
  2. 查看当前服务器管理区域。核对 IP、套餐和状态。本次看到的旧系统是 Debian 12；页面显示 Online 只说明机器已启动，不代表 SSH 密码正确。
  3. 进入横向菜单 Install → Reinstall OS。这里是系统重装表单，不选择 Control Panel 或 Applications。
  4. 在 Select OS 中选择 Ubuntu 24.04 LTS；没有时选 Debian 12。确认具体系统版本被选中。本教程后续命令适用于这两种系统，不适用于 CentOS / AlmaLinux。
  5. 在 New Password 填写新 root 密码，在 Retype Password 再填一次。使用新的强密码，保存到自己的密码管理工具；这不是 ColoCrossing 账号密码。密码由你在后台填写，不写进本教程。
  6. 若出现 Format Primary Disk Only，它表示只格式化第一块磁盘、保留附加磁盘。本次要清空整台 VPS 的所有磁盘时保持关闭；只清空系统盘、保留额外数据盘时打开。已知旧套餐为 30GB 系统盘，仍以后台实际磁盘配置为准，最终确认前核对要清空的范围。
  7. 从头建立 SSH 密钥时，打开 Remove old SSH Keys；Select SSH keys 暂不选择旧密钥。第 5 步会建立并验证新的日常管理密钥。
  8. 核对第 2 步已经确认可清空旧数据；如选择了保留数据分支，其备份已完整下载。然后由你点击 Reinstall 并完成页面最终确认。这个动作会按所选磁盘范围清空 VPS，包含系统盘。
  9. 进入 Tasks And Logs → Tasks 查看本次重装任务，等待该任务显示完成且服务器恢复 Online / Running。旧的 VPS Restart / VPS Start 成功记录不等于重装已完成。
  10. 重新核对公网 IP。若有变化，修改教程顶部的 IP，点击“更新教程参数”，再继续第 4 步。

详情页服务器管理区域顶部有一个显示器图标，提示为 Connect to the VPS via VNC.，这是网页控制台。与 Stop、Restart、Poweroff 图标相邻，先核对按钮提示再点击。看到 login: 后输入 root，Password 提示时输入本次设置的新密码；输入没有回显。以后 SSH 出错时从这里查看系统。

VNC 打不开，或一直显示 Not connected. Please try again.？

先区分：产品信息已经显示，但下面管理区域空白时，VNC 入口还未加载；能打开控制台但无法连接，是控制台连接阶段的问题。这个提示不能单独证明 VPS 停机。通过上面的干净产品链接重新进入，等待管理区域加载；不要刷新带 a=start、a=reboot 的操作地址。

管理区域出现后，点击 VNC 图标，再选 Launch HTML 5 VNC Client。没有新窗口时检查浏览器是否拦截了这个网站的弹窗。仍失败可换浏览器或手机热点各试一次，用来区分本地访问问题；持续失败时进入 ColoCrossing 建立服务单，请求恢复控制台、提供直接管理链接、确认本次重装任务完成，并从 VPS 控制台或宿主机读取第 4 步对应类型的 SSH SHA256 指纹。等待商家独立提供指纹后完成核对；不把同一条尚未核对的 SSH 连接里读出的值当成独立证明。

后续安装和网站发布使用 SSH。VNC 是首次核对和 SSH 故障时的备用入口；完成第 4 步核对后，不需要一直开着它。

Mac 登录 → 服务器 root 终端

第一次连接新系统，更新基础环境

按 ⌘ + 空格，搜索“终端 / Terminal”，打开一个新的 Mac 本地终端。此时类似 (base) ➜ ai-instructure ... 的提示符仍属于你的电脑；要先用 SSH 进入服务器，才能在服务器执行 apt、ss 等命令。

在 Mac 终端输入下面的命令并按回车。首次登录明确只尝试密码认证，避免本机 SSH agent 的多个密钥连续尝试：

Mac 本地终端 · 重装完成后
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password root@23.94.184.3

出现 root@...'s password: 后，输入第 3 步刚设置的新 root 密码，不是旧密码，也不是商家网站账号密码。输入时没有字符或星号回显，输完按回车。

首次连接如询问是否信任主机，先核对 SSH 提示中的密钥类型和 SHA256 指纹。在 ColoCrossing 的网页 VNC 控制台用新密码登录 root 后，按类型选择下面一条命令；本次实际 SSH 提示是 RSA，对应第一条。

ColoCrossing 网页 VNC · root · SSH 提示 RSA 时
ssh-keygen -lf /etc/ssh/ssh_host_rsa_key.pub -E sha256
ColoCrossing 网页 VNC · root · SSH 提示 ED25519 时
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub -E sha256

比较两处完整的 SHA256:... 字符串，必须逐字符一致；如果用 OCR 提取，最后再对照画面确认。输出开头的 3072 等数字是密钥长度，末尾 root@... 是备注，它们不参与指纹核对。不同密钥类型的指纹不能互相比。

VNC 输出与 SSH 提示一致后，才在 Mac 的确认提示中输入 yes。VNC 无法连接时，按第 3 步的工单路径请求商家独立读取指纹。以后再次重装，要重新核对当时的新指纹，不沿用本次的旧值。

出现 REMOTE HOST IDENTIFICATION HAS CHANGED 怎么办？

重装系统会换 SSH 主机密钥。确认是你刚刚重装的同一台 VPS、IP 一致，并通过控制台或商家工单核对新指纹后，在 Mac 执行下面的命令，只移除这个 IP 的旧记录，再重新连接。若同一类型的 SHA256 值前后又变了，先重新核对当前值；删除 known_hosts 记录不会改变服务器上的密钥。不要关闭 SSH 的主机密钥检查。

Mac 本地终端 · 核对重装与指纹后
ssh-keygen -R 23.94.184.3
ssh -o PubkeyAuthentication=no -o PreferredAuthentications=password root@23.94.184.3
Permission denied / Too many authentication failures 怎么办？

Permission denied 表示登录认证未通过；收到密码提示说明 SSH 连接已经建立，不再是端口拒绝问题。先确认本次重装任务已完成、用户名是 root，并使用刚设置的新密码。不要连续重复猜旧密码。

Too many authentication failures 表示该连接的认证失败次数达到上限，可能来自错误密码或多个密钥尝试。重新打开一次连接，使用上面的密码认证命令排除 SSH agent 密钥尝试。如果正确的新密码仍被拒绝，先用 VNC 控制台验证能否登录，再查看 SSH 配置或商家镜像设置；不要直接关闭认证保护。

Connection refused / Connection timed out 怎么办？

这两种提示都发生在登录验证之前。先核对 IP 和重装任务是否完成、服务器是否 Online，再通过 VNC 检查 SSH 是否监听 22，以及云防火墙和 UFW。Online 不能证明 SSH 服务已经正常。把具体提示发我，根据结果继续，不靠反复重装排查。

看到类似 root@服务器名称:~#，才说明已经进入服务器。后续命令逐条执行并核对结果。离开服务器时可输入 exit，返回 Mac 本地终端。

指纹核对并登录成功后，系统初始化、安装代理和部署网站都在 SSH 中继续；可以关闭 VNC 窗口，保留它作为以后 SSH 无法登录时的备用入口。

现在以下命令是在服务器的 root 终端上执行：

服务器终端 · root
cat /etc/os-release
free -h
df -h /
apt update
apt upgrade -y
apt install -y sudo curl wget ca-certificates nano ufw rsync unzip gnupg sqlite3

系统升级如询问是否保留 SSH 配置，先保留当前配置；如果提示必须重启，执行 reboot，等待云后台恢复 Running 后重新 SSH 登录。磁盘接近满、内存极少或 apt 报错时，先解决再继续。

成功条件：系统是 Ubuntu 24.04 或 Debian 12，更新命令没有失败，磁盘有可用空间。

建立日常管理员，并验证 SSH 密钥

旧教程使用 root + 密码登录。这次改用 deployer + SSH 密钥做日常上传和维护：私钥保存在 Mac，服务器保存公钥并验证登录；需要管理员权限时再用 sudo。这一步完成后，第 6 步才会关闭 root 和密码登录。

全程保留两个窗口。窗口 A 是已登录服务器的 root 终端；窗口 B 是 Mac 本地终端。根据命令框顶部的位置标签切换，每条命令成功后再继续。

只复制命令框里的内容。root@obvymadx:~#、(base) ➜ ~ 是位置提示，不是命令；ls: 等错误行是输出，也不要粘贴执行。直接使用命令框右上角的“复制命令”按钮。

5.1 在窗口 A 创建管理员

提示符类似 root@obvymadx:~#。这次固定把日常管理员叫 deployer；已经完成以下两条命令时跳过创建。

服务器终端 · root
adduser deployer
usermod -aG sudo deployer

adduser 会让你设置 deployer 的密码，后面使用 sudo 会用到它。姓名等可选项按回车跳过。

5.2 打开窗口 B，确认是在 Mac 上

保持窗口 A 打开。在 Mac 的“终端”应用里按 ⌘ + N，新开一个窗口；此时先不执行 SSH 登录。类似 (base) ➜ ~ 的提示符属于 Mac 本地。

窗口 B · Mac 本地终端
echo "$HOME"

应该输出 /Users/你的用户名，本次是 /Users/chenmao。若输出 /root，仍在服务器里，换到新开的 Mac 窗口再继续。$HOME 取的是当前机器、当前账号的家目录。

确认位置后，检查 Mac 上的专用密钥：

Mac 本地终端
ls -l "$HOME/.ssh/ironmao_vps" "$HOME/.ssh/ironmao_vps.pub"
  • 两份文件都存在：沿用它们，跳过生成命令。
  • 两份都显示 No such file or directory：Mac 还没有这套密钥，继续 5.3。
  • 只存在其中一份：先核对原因，避免覆盖正在使用的密钥。
若报错路径是 /root/.ssh/ironmao_vps，表示命令在服务器上执行；这个结果不能说明 Mac 上有没有密钥。回到窗口 B 重新检查。

5.3 在窗口 B 生成密钥

仅在 Mac 上两份文件都不存在时执行：

Mac 本地终端 · 仅在这套密钥不存在时
ssh-keygen -t ed25519 -f "$HOME/.ssh/ironmao_vps" -C "ironmao-vps"

Enter passphrase 询问的是保护 Mac 私钥文件的密钥口令。建议设置一个自己记得住的口令，再在 Enter same passphrase again 提示中输入一次；输入不会显示字符。

已经直接回车使用空口令，也可以继续安装和登录。区别是私钥文件没有口令加密保护，拿到文件的人少了一道使用门槛。无需重新生成密钥；需要补上口令时，展开下面的可选操作。

已经生成空口令密钥，怎样给它补上口令？

在 Mac 本地执行以下命令，修改同一份私钥的口令：

Mac 本地终端 · 可选：给现有私钥补口令
ssh-keygen -p -f "$HOME/.ssh/ironmao_vps"

若询问旧口令，原来为空就直接回车；然后按提示输入新口令两次。公钥不变，已经安装到服务器的公钥也无需重装。以后 SSH 可能询问这个密钥口令。

生成成功后会显示密钥保存位置。在窗口 B 再执行 5.2 的 ls 检查，应看到两份文件：ironmao_vps 是私钥，留在 Mac；ironmao_vps.pub 是下一步上传的公钥。

5.4 在窗口 B 上传公钥

PreferredAuthentications=password 必须原样保留。password 是“使用密码认证”的方式名称，不是让你替换成实际密码。实际密码只在执行命令后出现的交互提示里输入。
窗口 B · Mac 本地 · 用新 root 密码上传公钥
scp -o PubkeyAuthentication=no -o PreferredAuthentications=password "$HOME/.ssh/ironmao_vps.pub" root@23.94.184.3:/tmp/ironmao-vps.pub

出现 root@...'s password: 后，再输入第 3 步设置的 root 密码并回车。看到文件传输 100%、命令正常结束后继续；若连接关闭或认证失败，先检查上面的认证方式参数、当前 root 密码和第 4 步的故障说明。

误把实际密码写进命令或聊天了怎么办？

参数改回 PreferredAuthentications=password，在交互提示输入密码。若实际 root 密码已经进入命令历史或聊天记录，使用仍保留的服务器 root 窗口执行 passwd，按提示换成新的 root 密码并保存；以后需要 root 密码时用新值。不要把新密码作为命令参数、写进教程或发到聊天里。

5.5 切回窗口 A，安装公钥

确认窗口 A 的提示符仍为 root@obvymadx:~#，在服务器逐条执行以下两条命令。这是刚创建的 deployer 账号的首次安装；如果已有 authorized_keys 且包含其他要保留的公钥，先保留原文件并追加新公钥，不覆盖原授权。

窗口 A · 服务器 root · 公钥上传成功后

install -m 600 -o deployer -g deployer /tmp/ironmao-vps.pub /home/deployer/.ssh/authorized_keys

成功时通常没有输出，直接回到 root 提示符。若显示文件不存在或用户不存在，先补齐公钥上传或 deployer 创建步骤；不要跳过错误继续。

5.6 回到窗口 B，验证密钥登录和 sudo

窗口 B · Mac 本地终端 · 验证后变成 deployer 服务器窗口

sudo -v

其他网站怎样接进来？

  • 其它已验证的静态网站：为每站建立 /srv/www/站名，上传发布文件，添加独立 Caddy 站点块与 DNS 记录；保留已有站点配置。
  • 论文精读页面：先整理拟公开的网页、Markdown 和引用资源，核对相对路径及公开范围，再按静态站部署；不直接上传整份研究目录和模型训练数据。
