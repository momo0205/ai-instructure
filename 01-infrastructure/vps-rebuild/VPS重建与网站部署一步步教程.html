02

旧服务器 + Mac · 重装前完成

把旧配置备份到电脑

先用你现在能登录的方法进入旧服务器。重装会清空系统盘。下面只备份常见的代理、Caddy 和网站目录，不等于整机备份。若旧机还有数据库、容器或其它应用，先额外导出这些应用的数据，再继续。

先看看原来跑了哪些服务：

旧服务器终端 · 已登录的账号
sudo ss -lntp
df -h /
sudo ls -ld /etc/x-ui /etc/caddy /srv /var/www

不存在的目录会显示 “No such file or directory”，这是检查结果。确认只有旧代理或这些网站目录后，生成备份：

如果旧服务仍在写数据库，先在 3X-UI 面板的数据库备份功能里导出并下载数据库，或先暂停对应服务再执行下面的备份；运行中的 SQLite 文件不能靠普通复制保证一致性。
旧服务器终端
sudo bash -c '
set -eu
set --
for backup_dir in /etc/x-ui /usr/local/x-ui /etc/caddy /root/cert /srv /var/www; do
  if [ -e "$backup_dir" ]; then set -- "$@" "$backup_dir"; fi
done
if [ "$#" -eq 0 ]; then
  echo "未找到这些服务目录，请先核对其它数据位置"
  exit 1
fi
tar -czf /root/vps-before-reset.tar.gz "$@"
chmod 600 /root/vps-before-reset.tar.gz
tar -tzf /root/vps-before-reset.tar.gz > /dev/null
tar -tzf /root/vps-before-reset.tar.gz | head -20
'

打开一个新的 Mac 本地终端，把备份下载到桌面。这里用旧记录中的 root 登录方式；如你原来用密钥，给 scp 加上同一个 -i 密钥路径。如果 root 登录已被关闭，使用你的管理员账号将备份复制到它的家目录、设置仅该账号可读，再用这个账号下载。

Mac 本地终端 · 不是 SSH 里的终端
(
set -eu
scp root@23.94.184.3:/root/vps-before-reset.tar.gz "$HOME/Desktop/vps-before-reset.tar.gz"
chmod 600 "$HOME/Desktop/vps-before-reset.tar.gz"
tar -tzf "$HOME/Desktop/vps-before-reset.tar.gz" > /dev/null
tar -tzf "$HOME/Desktop/vps-before-reset.tar.gz" | head -20
)

成功条件：SCP 下载成功，完整归档检查没有错误，再预览内容；仅看到前 20 项不能证明备份完整。旧面板如有数据库导出，也已下载到电脑。服务曾使用自定义证书路径时，一并备份该路径。

03

浏览器 · 这是清空系统盘的一步

登录 ColoCrossing，重装系统

  1. 打开 cloud.colocrossing.com，登录购买服务器的账号。
  2. 进入服务器列表，打开你这台洛杉矶 VPS 的详情。核对 IP、套餐、续费状态，避免选错机器。
  3. 找到 Reinstall / Reinstall OS / 重装系统 功能。界面可能把它放在操作菜单或系统设置里，按钮名称和位置以当前账号页面为准。
  4. 选择 Ubuntu 24.04 LTS；如果没有，可以选择 Debian 12。本教程后续命令适用于这两种系统，不适用于 CentOS / AlmaLinux。
  5. 按页面要求设置或获取 root 初始密码，保存在密码管理工具中。
  6. 确认第 2 步的备份已下载且能读取，再点击重装的最终确认按钮。等待部署结束、状态回到 Running。
  7. 重新核对公网 IP。若有变化，修改教程顶部的 IP，点击“更新教程参数”。

在同一个详情页面，找到 Console / VNC / 控制台 入口并确认能打开。以后 SSH 配置出错时，可以从这里登录系统修复。

成功条件：云后台显示系统重装完成，知道新的 root 密码和当前 IP，并能进入控制台。

ColoCrossing 官方确认云后台提供系统重装和网络控制；具体账号界面需现场核对：云后台功能说明。

04

Mac 登录 → 服务器 root 终端

第一次连接新系统，更新基础环境

在 Mac 的新终端里执行：

Mac 本地终端
ssh root@23.94.184.3

输入刚获得的 root 密码。输入密码时屏幕不会显示字符，输入完按回车即可。首次连接前，核对主机指纹：在 ColoCrossing 控制台运行下面的命令，比较终端提示的 SHA256 指纹。

ColoCrossing 网页控制台 · 登录 root 后
ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub
出现 REMOTE HOST IDENTIFICATION HAS CHANGED 怎么办？

重装系统会换 SSH 主机密钥。确认是你刚刚重装的同一台 VPS、IP 一致，并通过控制台核对新指纹后，在 Mac 执行下面的命令，只移除这个 IP 的旧记录，再重新连接。不要关闭 SSH 的主机密钥检查。

Mac 本地终端 · 核对重装与指纹后
ssh-keygen -R 23.94.184.3
ssh root@23.94.184.3

看到 root@...:~# 后，以下命令是在服务器上执行：

服务器终端 · root
cat /etc/os-release
free -h
df -h /
apt update
apt upgrade -y
apt install -y sudo curl wget ca-certificates nano ufw rsync unzip gnupg sqlite3

系统升级如询问是否保留 SSH 配置，先保留当前配置；如果提示必须重启，执行 reboot，等待云后台恢复 Running 后重新 SSH 登录。磁盘接近满、内存极少或 apt 报错时，先解决再继续。

成功条件：系统是 Ubuntu 24.04 或 Debian 12，更新命令没有失败，磁盘有可用空间。

05

服务器 root + Mac 新终端

建立日常管理员，并验证 SSH 密钥

这次固定把日常管理员叫 deployer，用于后续网站上传和维护。

服务器终端 · root
adduser deployer
usermod -aG sudo deployer

adduser 会让你设置 deployer 的密码，后面使用 sudo 会用到它。姓名等可选项按回车跳过。

打开新的 Mac 本地终端，检查专用密钥是否已存在：

Mac 本地终端
ls -l "$HOME/.ssh/ironmao_vps" "$HOME/.ssh/ironmao_vps.pub"

两份文件都存在时，沿用它们，跳过生成命令。不存在时生成；若只存在其中一份，先核对原因，避免覆盖正在使用的密钥。

Mac 本地终端 · 仅在这套密钥不存在时
ssh-keygen -t ed25519 -f "$HOME/.ssh/ironmao_vps" -C "ironmao-vps"

按提示设置密钥口令。上传公钥：

Mac 本地终端
scp "$HOME/.ssh/ironmao_vps.pub" root@23.94.184.3:/tmp/ironmao-vps.pub
服务器终端 · root
install -d -m 700 -o deployer -g deployer /home/deployer/.ssh
install -m 600 -o deployer -g deployer /tmp/ironmao-vps.pub /home/deployer/.ssh/authorized_keys

保持原来的 root 窗口打开，用 Mac 的另一个窗口验证：

Mac 本地终端 · 打开一个新窗口
ssh -i "$HOME/.ssh/ironmao_vps" -o PreferredAuthentications=publickey -o PasswordAuthentication=no -o KbdInteractiveAuthentication=no deployer@23.94.184.3
新连接的服务器终端 · deployer
whoami
sudo -v

成功条件：这个命令禁止回退到账号密码，必须通过公钥认证建立连接；whoami 输出 deployer，sudo -v 输入 deployer 密码后成功。后面默认使用这个服务器窗口。密钥有口令时，SSH 询问的是密钥口令；sudo 询问的是 deployer 密码。

06

Cloud 后台 + 服务器 deployer

配置两层防火墙，再收紧 SSH

有两层防火墙：商家的云防火墙，以及服务器自己的 UFW。都需要允许下面四组 TCP 端口：

端口用途云防火墙建议
22SSH先确保你的连接来源可访问
80网站跳转与证书验证允许入站
443网站 HTTPS允许入站
8443Reality允许入站
  1. 回到 ColoCrossing 云后台，打开这台 VPS 的 Firewall / 防火墙。
  2. 如果已绑定一个默认拒绝入站的规则计划，添加允许 TCP 22、80、443、8443 的入站规则；确认出口仍可访问互联网。
  3. 若当前未绑定云防火墙计划，先保持现状，完成下面的 UFW 配置。需要绑定新计划时，先建好 SSH 允许规则，再绑定到 VPS。不要先启用拒绝策略再补规则。
服务器终端 · deployer
sudo ufw default deny incoming
sudo ufw default allow outgoing
sudo ufw allow 22/tcp
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw allow 8443/tcp
sudo ufw enable
sudo ufw status verbose

确认四组 TCP 端口都是 ALLOW。这个新系统不需要向公网开放 18080、18081 或默认面板端口 2053。

只有第 5 步的新窗口登录和 sudo 已验证成功后，才执行：

服务器终端 · deployer
sudo tee /etc/ssh/sshd_config.d/00-ironmao.conf > /dev/null <<'EOF'
PubkeyAuthentication yes
PasswordAuthentication no
KbdInteractiveAuthentication no
PermitRootLogin no
EOF
sudo /usr/sbin/sshd -t
sudo /usr/sbin/sshd -T | grep -E '^(pubkeyauthentication|passwordauthentication|kbdinteractiveauthentication|permitrootlogin) '

第一条检查应无错误；第二条应显示公钥认证 yes，另外三项 no。输出不符合时，先检查 SSH 配置的 Include 和其它配置项，不执行下面的 reload。

服务器终端 · 四项检查正确后
sudo systemctl reload ssh

在 Mac 再开一个窗口，用第 5 步的密钥命令验证新连接。保持原有会话，直到新连接与 sudo 都成功。

可选：开启原版 BBR

仅使用现有系统内核。下面的 modprobe 成功后再继续；如果提示内核不支持，跳过，不更换内核。

服务器终端 · deployer
sudo modprobe tcp_bbr
sysctl net.ipv4.tcp_available_congestion_control

输出包含 bbr 时写入：

服务器终端 · 现有内核支持 BBR 时
sudo tee /etc/sysctl.d/99-ironmao-bbr.conf > /dev/null <<'EOF'
net.core.default_qdisc=fq
net.ipv4.tcp_congestion_control=bbr
EOF
sudo sysctl --system
sysctl net.ipv4.tcp_congestion_control

成功条件：UFW 开启后仍能建立新的 deployer SSH 连接；SSH 配置检查正确。

08

Mac 本地终端 + 浏览器

通过 SSH 隧道打开面板

在 Mac 新的终端窗口运行下面的命令。这是隧道窗口，连接后通常没有提示符；保持它打开：

Mac 本地终端 · 保持这个窗口运行
ssh -i "$HOME/.ssh/ironmao_vps" -N -L 127.0.0.1:18080:127.0.0.1:18080 -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 deployer@23.94.184.3

打开浏览器，输入：

http://127.0.0.1:18080/安装输出的WebBasePath/

填写 WebBasePath 后打开本地面板 ↗

用第 7 步保存的用户名和密码登录。这个地址的 HTTP 流量在你的 Mac 回环接口和服务器回环接口上，跨网络的一段由 SSH 加密。面板无需单独申请公网证书。

页面打不开时检查什么？
  • 隧道窗口是否仍开着，是否显示转发失败？
  • WebBasePath 是否使用了本次新安装输出的值？网址末尾保留 /。
  • 第 7 步的 x-ui 服务是否为 active？
  • 如果 Mac 的 18080 被占用，把隧道命令左侧的 127.0.0.1:18080 改成 127.0.0.1:28080，并用浏览器访问 28080；服务器端仍为 18080。

成功条件：看到 3X-UI 仪表盘，并能登录。

下面用 SQLite 自带的在线备份，避免直接复制正在写入的数据库。备份包含节点凭据，应存放在自己的受保护目录中。

服务器终端 · deployer
(
set -eu
sudo install -d -m 700 /var/backups/ironmao
BACKUP_STAMP="$(date -u +%Y%m%dT%H%M%SZ)"
sudo sqlite3 /etc/x-ui/x-ui.db ".backup '/var/backups/ironmao/x-ui-$BACKUP_STAMP.db'"
sudo tar -czf "/var/backups/ironmao/site-$BACKUP_STAMP.tar.gz" /etc/caddy /srv/www
sudo tar -tzf "/var/backups/ironmao/site-$BACKUP_STAMP.tar.gz" > /dev/null
sudo tar -czf "/var/backups/ironmao/bundle-$BACKUP_STAMP.tar.gz" -C /var/backups/ironmao "x-ui-$BACKUP_STAMP.db" "site-$BACKUP_STAMP.tar.gz"
sudo tar -tzf "/var/backups/ironmao/bundle-$BACKUP_STAMP.tar.gz" > /dev/null
sudo chmod 600 "/var/backups/ironmao/bundle-$BACKUP_STAMP.tar.gz"
sudo cp "/var/backups/ironmao/bundle-$BACKUP_STAMP.tar.gz" /var/backups/ironmao/ironmao-latest.next.tar.gz
sudo mv -f /var/backups/ironmao/ironmao-latest.next.tar.gz /var/backups/ironmao/ironmao-latest.tar.gz
sudo cp /var/backups/ironmao/ironmao-latest.tar.gz "$HOME/ironmao-latest.tar.gz"
sudo chown deployer:deployer "$HOME/ironmao-latest.tar.gz"
chmod 600 "$HOME/ironmao-latest.tar.gz"
)

每月维护

在 ColoCrossing 查看续费和流量；在服务器执行 sudo apt update、sudo apt upgrade。Caddy 会自动续证，保留正确 DNS 和 80/443。更新 3X-UI 前先备份，阅读官方发布说明，再从 sudo x-ui 的管理菜单更新，更新后重新验证所有客户端。

其他网站怎样接进来？

  • 其它已验证的静态网站：为每站建立 /srv/www/站名，上传发布文件，添加独立 Caddy 站点块与 DNS 记录；保留已有站点配置。
  • 论文精读页面：先整理拟公开的网页、Markdown 和引用资源，核对相对路径及公开范围，再按静态站部署；不直接上传整份研究目录和模型训练数据。
  • A 股工作台、Mira、Agent Evidence Lab：属于后台应用，需要另外设计身份认证、运行服务、状态持久化、数据库/任务和资源容量。本教程的静态文件配置不适用于这些后台。

成功条件：重启后新 SSH、代理和网站都正常；备份已下载且可列出内容，知道实际使用的端口和更新方法。

遇到问题时，停在当前步骤

把步骤编号、在哪个终端执行、命令和错误输出给我。不要发送密码、私钥、完整节点链接或含登录凭据的面板输出。

症状先检查
SSH 超时ColoCrossing 状态与 IP → 云防火墙 22 → 控制台 → UFW
面板打不开SSH 隧道是否运行 → 本次 WebBasePath → x-ui 服务 → 127.0.0.1:18080
Reality 握手失败8443、UUID、Vision、SNI、公钥、Short ID 与客户端版本；查看 x-ui/Xray 日志
网站证书失败A/AAAA → 两层防火墙 80/443 → Caddy 日志
首页正常，课程打不开完整 dist/client 是否上传；.html 路径映射、.rsc 文件和 Content-Type
橙云后错误先回灰云比较；确认 VPS HTTPS 已正常、Full (strict) 与现有域名配置兼容
