## 已定方案与处理过的问题

- 原 3X-UI 路线后来让位于固定版本 sing-box 路线，原因包括 FlClash / Mihomo 与较新 Xray 的兼容性风险，以及订阅操作过于繁琐。后续以新的实测教程为准。
- 代理使用 443；Caddy 订阅使用 HTTPS 8443。订阅采用正常公网 URL，日常设备使用无需 SSH 隧道。
- Caddy Cloudsmith 软件源曾返回 HTTP 402。用户已暂时停用该源，apt update 恢复、Caddy 保持 active，并随后完成 sing-box 安装；后续需恢复可靠的 Caddy 更新途径。
- 配置生成器已成功执行，重复执行触发防覆盖保护。不要为解决网速问题反复生成密钥或客户端文件。

## 后续工作顺序

1. **定位速度和超时。** 在实际出现问题的设备上启动 FlClash，固定选择新节点，用显式代理测试同一个下载目标。对比当前网络与手机热点，并在不同时段重复；记录成功率、耗时、速度和同一时段的 sing-box 日志。再决定是否调整客户端、当前网络或 VPS 线路。
2. **补齐订阅与多设备验收。** 核对第 11 步是否实际完成：证书可信、私密订阅下载 HTTP 200、FlClash URL 导入与更新成功。用第二台设备导入并验证。真实 URL 含节点凭据，仅保存在用户自己的密码管理工具中。
3. **完成维护与恢复验收。** 做配置备份并下载到 Mac；在方便的时间验证服务器重启后 SSH、sing-box、Caddy 和订阅均恢复。核对固定版本更新策略、停用的 Caddy 更新源，以及历史对话中出现的疑似明文密码是否已更换。维护手册中的旧面板 / 旧订阅内容需要与现行路线统一。
4. **确定网站与代理共存方案。** 当前 Reality 独占同一 IP 的 TCP 443，旧教程的普通网站 HTTPS 配置会冲突。先选择独立承载、额外 IP，或另行设计并实测协议复用，再更新网站教程并部署金融学习站、Agent 工程笔记。
5. **另做后台应用部署。** A 股工作台、Mira 等需要独立处理认证、数据库、资源占用与备份，不属于静态网站上传流程。

## 最后一次测速的证据边界

历史测试：VPS 负载接近 0，可用内存约 617 MiB；VPS 下载外网文件约 4.1–4.6 MB/s；这台 Mac 到 VPS 建连约 355–381 ms；VPS 到 Mac 的 5 MiB SSH 传输约 15.8 s，平均 0.33 MB/s（包含建连时间）。

这些结果更支持设备到 VPS 路径较慢，尚不足以认定服务器硬件不足或某个运营商线路有问题。当时 Mac 的 FlClash 未监听 7890，未测到完整代理速度，也没有复现超时。当前网络与手机热点的对比仍未见后续结果。
