# A 股事件驱动选股与日线回测系统设计

## 1. 背景与目标

用户当前策略大部分时间空仓，仅在满足“大盘点位高于阈值且当日下跌”时买入一个标的，并在后续交易日卖出。当前唯一可变因素是买入哪支股票/ETF，默认使用科创 50 ETF。

本项目新建为独立子项目 `04-applications/investment-research/a-stock-strategy`，不修改 Mira（投研协议）或 gridbot（现有交易机器人）。第一版目标是验证动态选股是否能相对固定科创 50 ETF 提升风险调整后收益，并为未来的推荐、图表和分钟线回测保留稳定接口。

本系统是研究与模拟工具，不是投资建议、自动下单或实盘交易系统。

## 2. 范围与非目标

### 第一版范围

- 仅支持日线 OHLCV 数据。
- 以收盘后可获得的数据生成信号。
- 默认在下一交易日开盘模拟买入，并在持有期结束时按配置价格模拟卖出；默认持有 1 个交易日。
- 支持固定科创 50 ETF 基准和至少一个动态横截面选股策略。
- 支持本地 CSV/Parquet 数据；数据源通过接口抽象，后续可接入 A 股数据适配器。
- 输出逐笔交易、净值曲线、指标汇总和静态图表。
- 在指定交易日输出候选标的排名与特征解释。

### 非目标

- 第一版不接实盘账户、券商 API 或自动下单。
- 第一版不做分钟级撮合、盘中实时信号和异步行情服务。
- 第一版不引入机器学习模型、复杂组合优化或新闻情绪模型。
- 第一版不把 Web 前端作为交付阻塞项；CLI、JSON/CSV 和静态图优先。

## 3. 架构方案

采用模块化 Python 核心 + CLI/API 的渐进式架构：

```text
标准化行情数据
      |
      v
市场状态/事件判定 ---> 候选池 ---> 策略评分 ---> 信号
                                      |
                                      v
                             日线撮合回测引擎
                                      |
                                      v
                             交易记录/净值/指标
                                      |
                                      +--> 静态报告
                                      +--> 推荐接口（未来）
```

模块边界：

- `data`：`MarketDataProvider` 及 CSV/Parquet 适配器；负责字段标准化、交易日索引和数据质量校验。
- `domain`：行情、市场事件、信号、订单、成交、组合快照等不可变领域模型。
- `strategies`：统一 `Strategy` 协议；包含固定标的基准与动态评分策略。
- `backtest`：按交易日推进，处理现金、持仓、成本、滑点、停牌/涨跌停不可成交等规则。
- `evaluation`：从权益曲线和成交记录计算指标与基准对比。
- `reporting`：JSON/CSV 序列化与 matplotlib 静态图；不反向依赖策略实现。
- `recommendation`：在最新可用日期执行策略，返回排序、分数、特征和风险提示。
- `config`/CLI：YAML 或 TOML 配置，确保阈值、成本、候选池和策略权重可复现。

## 4. 核心数据契约

### 日线行情

每行至少包含：`date`, `symbol`, `open`, `high`, `low`, `close`, `volume`, `amount`, `is_suspended`, `limit_up`, `limit_down`。日期使用交易所本地日历，价格字段必须明确前复权或后复权口径；回测配置必须记录该口径。

### 市场状态

市场状态计算器输入指数或用户配置的市场代理行情，输出：

- `index_level`
- `index_return_1d`
- `triggered`（是否满足点位和下跌条件）
- `as_of`

第一版不假设“4000+”对应某个具体指数代码，必须在配置中显式指定市场代理与阈值。

### 策略接口

策略以截至当前交易日的数据快照和市场状态为输入，返回零个或一个目标标的及解释信息。禁止读取未来日期数据。

```python
class Strategy(Protocol):
    def select(
        self,
        as_of: date,
        market: MarketState,
        universe: pd.DataFrame,
    ) -> Selection | None: ...
```

`Selection` 至少包含 `symbol`, `score`, `features`, `reason`。

## 5. 回测时序与交易规则

每个交易日按以下顺序执行：

1. 加载截至当日收盘的数据；
2. 计算市场状态和选股特征；
3. 若已有持仓，先按退出规则生成卖出订单；
4. 若无持仓且市场事件触发，生成目标标的买入信号；
5. 信号在下一交易日开盘执行，使用配置的滑点；
6. 持仓达到持有期后，在下一可交易日按配置价格卖出；
7. 扣除佣金、印花税和滑点，更新现金、持仓和权益曲线。

为了避免未来数据泄漏，禁止用信号日收盘之后才知道的字段计算信号，也禁止用未来复权信息或未来成分股列表替代当时可获得的数据。

第一版默认成本参数需可配置，并在报告中回显；A 股卖出印花税、佣金、最低佣金和滑点不能硬编码在策略中。

## 6. 第一版策略

- `FixedAssetStrategy`：事件触发时买入固定代码（默认科创 50 ETF），用于基准。
- `CrossSectionalRankStrategy`：在配置候选池中计算可解释的日线特征（例如过去 N 日动量、短期反转、波动率、成交量变化），按标准化加权得分选择最高分；缺失数据、停牌、涨跌停不可买入的标的不参与排序。

策略权重、窗口、候选池和最低流动性门槛全部外置配置，禁止在代码中散落常数。

## 7. 评估与报告

必须输出：累计收益、年化收益、胜率、平均盈亏、盈亏比、最大回撤、年化波动率、夏普（无风险利率可配置）、交易次数、空仓比例、基准收益和超额收益。

报告文件包括：

- `trades.csv`：信号日、买入日、卖出日、标的、价格、数量、费用、收益、退出原因。
- `equity.csv`：每日现金、持仓市值、总权益、回撤。
- `summary.json`：配置摘要、数据范围、指标、警告。
- `report.png`：权益曲线、回撤曲线、按年份收益柱状图（若数据足够）。

所有报告必须包含数据来源、复权口径、回测时间范围、成本参数和生成时间。

## 8. 推荐能力（第一版接口，后续增强）

推荐模块复用回测策略，在指定 `as_of` 日期运行一次，返回：

- 是否触发市场事件；
- 候选池及过滤原因；
- 排名、分数、特征值和文字化理由；
- 数据质量警告和风险提示。

推荐结果明确标注为研究输出，不得伪装为确定性买卖指令。

## 9. 错误处理与数据质量

- 缺少必需列、重复主键、非单调日期、价格非正数时立即失败并给出文件与行号。
- 缺失特征只允许按策略显式配置的规则处理；不能静默填充为未来值。
- 停牌、涨跌停和无下一交易日时生成不可成交/未完成状态，不能假设成交。
- 数据源不可用时，回测只能使用已下载的本地数据；不在回测过程中隐式联网。
- 所有警告进入 `summary.json` 和 CLI 输出。

## 10. 测试与验收标准

测试采用 pytest，先测试后实现。至少覆盖：

- 事件触发只使用当日及以前数据；
- 买入和卖出日期严格符合持有期；
- 佣金、印花税、滑点正确计入；
- 停牌/涨停不可成交；
- 固定策略与动态策略都能通过同一回测接口运行；
- 基准比较指标一致；
- 缺失列、重复数据和错误日期被拒绝；
- 推荐输出与回测在同一 `as_of` 日期下的选择结果一致。

验收以一份小型固定 fixture 数据完成端到端回测，并能生成四类报告文件；不要求联网即可运行测试。

## 11. 后续演进

在第一版通过验收后，再按优先级增加：分钟线数据适配器与盘中撮合、FastAPI 查询接口、Web 图表、策略参数扫描/走步回测、更多 ETF/个股特征、模型策略和实盘前风控沙盒。所有扩展必须复用现有数据与策略协议，不改变基础回测时序语义。
