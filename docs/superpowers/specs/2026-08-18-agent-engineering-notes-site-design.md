# Agent 工程笔记网站设计

日期：2026-08-18  
状态：待所有者书面审核  
目标公开仓库：`agent-engineering-notes`

## 1. 目标

建立一个独立、公开、可持续维护的中文技术内容站，记录一名 Java 工程师从 LLM API、Tool Calling
走向 Context Engineering、Harness、RAG、Agent Loop、Evaluation 与生产部署的真实学习过程。

网站名称为 **Agent 工程笔记**。它不是 AI 名词目录，也不直接公开私人工作区，而是把真实代码、
实验、失败和架构判断整理成经过脱敏、可复核的公开内容。

首发只围绕 Agent Evidence Lab，避免一次覆盖整个 `ai-instructure` 导致主题松散和脱敏风险扩大。

## 2. 用户与内容原则

主要读者：

- 已有后端开发经验、正在转向 Agent 工程的开发者；
- 希望理解 Context、Harness、ReAct/RAG 和 Evaluation 如何落到代码的人；
- 不满足于框架教程，希望看到真实权衡、失败和验证过程的人。

内容原则：

1. 先讲人能理解的问题和决策，再讲类、接口和代码。
2. 清楚区分“已经实现”“实验验证”“尚未完成”和“未来方向”。
3. 不把小型评测外推为普遍结论。
4. 每个重要结论尽量关联代码、测试、实验或官方来源。
5. 默认不公开私人工作区内容，只有明确进入公开仓库的材料才允许发布。

## 3. 首发范围

### 3.1 页面

```text
/
├── /journey
├── /articles
├── /articles/{slug}
├── /projects/agent-evidence-lab
└── /about
```

- 首页：解释网站是谁写的、为什么存在，突出当前项目并引导阅读。
- 学习路线：展示从 Java 后端到 Agent Engineering 的阶段和依赖关系。
- 文章列表：按学习路径、工程实践、真实复盘等类型浏览。
- 文章详情：承载 Markdown/MDX 内容、目录、代码和图示。
- 项目页：持续反映 Agent Evidence Lab 的完成度、评测证据和下一步。
- 关于：说明作者背景、写作原则、脱敏策略和免责声明。

### 3.2 首批文章

1. 《从 Java 后端到 Agent 开发，技术栈到底变了什么》
2. 《Agent = LLM + Context + Harness，在代码里分别是什么》
3. 《第一个受约束 Agent Loop：完成了什么，还缺什么》
4. 《为什么模型把“明确反对”判断成了支持》
5. 《Java 还是 Python：我如何选择 Agent 执行面》

每篇文章至少包含：学习阶段、阅读时间、关键结论、架构图或流程图、对应代码、真实踩坑、适用边界和更新时间。

## 4. 视觉系统

设计目标是克制、高级、有人味，减少常见 AI 模板感。参考 Apple、Chrome 和优质个人创作者网站的
内容层级与留白，但不复制任何具体页面。

已确认方向：

- 暖白页面背景；
- 深靛蓝的主项目色块；
- 蓝灰、绿灰、暖灰等同明度、低饱和文章卡；
- 所有色块共享同一圆角、间距、字阶和交互语言；
- 中文字体承担标题与正文，等宽字体只用于日期、分类和技术元信息；
- 首页以个人学习叙事为中心，不使用网格纸、状态面板、标签墙或大段全大写英文；
- 不依赖高成本动画、视差滚动或赛博光效；
- 手机与桌面端使用同一内容层级。

首页核心文案方向：

> 我在学习怎样造出真正能工作的 Agent。  
> 这里记录一路上的代码、失败和判断。

视觉确认稿保存在私有工作区的 Superpowers brainstorm 会话中，正式实现应复用其内容层级和色彩关系，
但不能把临时画布代码直接当成生产页面。

## 5. 技术架构

采用自定义 React/Vinext 内容站，而不是套用完整文档主题：

- React/Vinext：页面和布局；
- Markdown/MDX：文章内容；
- 严格 Frontmatter Schema：标题、摘要、状态、发布时间、更新时间、类型、阅读时间和标签；
- 构建期静态内容索引：首版搜索；
- Git：内容版本与发布历史；
- Sites：首个在线预览与托管；
- GitHub：公开源代码仓库；
- 后续可按需要连接 Cloudflare Pages 或自定义域名，但不作为首次上线前置条件。

第一版不需要数据库、用户登录、评论、CMS、服务端搜索、访问统计或 AI 问答。

## 6. 内容状态与发布

文章状态：

- `draft`：仅本地存在，不进入公开构建；
- `review`：允许生成预览，不出现在生产导航和索引；
- `published`：通过所有检查并经所有者确认后公开。

发布流程：

```text
私人 ai-instructure
  → Codex 扫描候选材料
  → 公开草稿 + 敏感项报告
  → 自动检查
  → 陈矛审核观点与公开边界
  → 公开仓库 PR/提交
  → 在线预览
  → 正式发布
```

内容挑选是陈矛与 Codex 的共同工作：Codex 负责扫描、归类、脱敏和起草；陈矛负责确认公开范围、
个人观点和最终发布状态。未经确认的材料不能进入 `published`。

## 7. 脱敏与版权边界

自动扫描应阻止：

- API Key、Token、Cookie 和 Authorization Header；
- SSH 私钥、数据库连接串和 `.env` 内容；
- 公网/内网 IP、服务器用户名和本机绝对路径；
- 私有仓库地址、Cloudflare Tunnel 配置；
- 邮箱、手机号、投资账户与私人业务数据。

人工语义检查应覆盖：

- 服务器和网络拓扑能否被推导；
- 是否暴露私人身份、资产或内部对话；
- 是否包含未经许可的第三方源码或大段受版权保护内容；
- 是否把旧状态写成当前状态；
- 是否把局部实验夸大为通用事实。

构建只能读取公开仓库内的白名单内容目录，不能在 CI 中扫描或读取整个私人 `ai-instructure`。

## 8. 失败处理与质量门

- Frontmatter 缺字段或类型错误：构建失败；
- 内部链接失效：构建失败；
- 敏感信息命中：构建失败；
- `draft`/`review` 混入生产导航：测试失败；
- 部署失败：保留上一版线上站点；
- 页面视觉异常：在 Preview 中修正后再发布。

测试范围：

- 路由与内容 Schema；
- 脱敏扫描器及其正反例；
- 生产构建；
- 内部链接；
- 桌面和移动端页面；
- 键盘导航、焦点、标题层级和颜色对比度；
- 发布后首页与文章页 Smoke Test。

## 9. SEO 与分发

第一版提供：

- 每页独立 title/description；
- canonical URL；
- Open Graph 与社交分享图；
- sitemap；
- RSS；
- 语义化标题和文章发布时间。

自定义域名不是首发阻塞项。先使用免费预览/托管地址验证内容与更新流程，再购买和绑定域名。

## 10. 仓库与账号交接

目标公开仓库使用 `agent-engineering-notes`。私人工作区只保存原始材料和设计历史，公开站点拥有独立 Git 历史。

若切换 Codex 账号，新账号应先阅读：

1. 工作区 `AGENTS.md`；
2. 本设计文档；
3. 后续实施计划；
4. `agent-engineering-notes` 最近提交和 README；
5. 交接文档中的未完成步骤。

不复制 `~/.codex`、认证 Token 或账号状态。代码、规格、计划和 Git 提交是跨账号交接的事实来源。

## 11. 完成标准

MVP 完成必须同时满足：

- 六个首发页面可访问；
- 五篇文章至少三篇达到 `published`，其余可保持 `review`；
- 视觉实现与已确认方向一致；
- 手机与桌面端可用；
- 自动脱敏、Schema、链接和构建检查通过；
- 独立公开 GitHub 仓库存在；
- 在线预览可访问；
- 没有把私人工作区、密钥或内部配置纳入公开构建；
- README 写清本地写作、审核和发布流程。
