# 看懂策略和每次买卖

## 从哪里看

1. 打开工作台「策略回测」，选择本地动量或 Qlib 动量。
2. 表单底部的「本次策略规则」会跟随候选、窗口、最低动量、市场阈值和持有期变化。市场阈值页面单位为百分数，最低动量为小数（0.05 = 5%）。
3. 用合成样例先运行：窗口2、最低动量-1、持有3日，其余默认。-1只是功能验收参数，不是投资建议。
4. 结果中展开「本次任务的策略规则（冻结参数）」；它来自任务原请求，不受当前表单修改影响。
5. 「为什么选它 · 逐日决策」默认定位首次选中证券的日期。切换日期查看下跌家数、指数收益、是否触发、每只候选的实际分数、参考价与落选原因。
6. 「交易时间线」对照信号日、计划买入日、执行日、实际买入日、计划卖出日。取消买入不会伪造实际买入日；卖出顺延保留原计划日。

## 如何理解

- 公式：当日收盘价 / N个交易日前收盘价 - 1。达到最低动量的候选中取最高一只；同分按证券代码升序。
- 仅空仓且市场条件触发时择股。持仓日不重新计算候选，不加仓、不换仓；没有止盈止损。
- 数据不足、无效价格、已知停牌或涨跌停会排除候选。未知状态按可成交假设处理；False 不表示已经验证。
- Qlib 分数是因子引擎实际输出，本地分数是本地计算；内部精度可能产生微小差异。
- 收盘信号安排下一交易日开盘买入。买入后经过H个交易日，在开盘尝试卖出。买入受阻取消，卖出受阻顺延。计划日超出样本时显示未知，不推算样本外日历。
- 市场数据缺失显示无法判断及数据说明；不会将其伪装成实际0%收益。
- 排名高只表示过去这段时间相对强，不代表预测未来上涨。页面展示历史决定，不是实时交易建议。

## 本轮范围

逐候选分数与排除原因支持本地动量、Qlib动量。固定标的和横截面排名仍可查看市场状态、选中证券及执行时间线；尚未提供横截面各因子的贡献分解。

旧任务没有运行时决策记录，会提示复制参数重跑。原任务结果不改写。新 JSON 的 decision_events 包含逐日证据，execution_events 包含订单关联日期，随结果同步至 MLflow。

## 快速验收

- 将窗口2改为5、持有3改为1，规则卡随之更新；提交后结果卡保留提交时参数。
- 在触发日确认获选证券分数最高且满足门槛；合格但落选的证券显示分数或同分原因。
- 查看持仓日：显示不重新择股，不出现假想候选评分。
- 比对信号日与下一交易日实际买入；持有期从实际买入日计算。
- 旧任务显示重跑提示；复制重跑生成独立新结果。
