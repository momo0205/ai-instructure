# 平台完整验收教程

适用版本：2026-09-20 本地工作台。目标是验证平台能否正确执行、保存和解释研究任务，不是验证某个策略一定赚钱。

预计需要45–90分钟，外部行情下载和 Qlib 任务可能增加时间。建议按顺序完成 A–H；I 是异常及恢复检查。每做完一项，在文末验收表记录任务编号和现象。不要删除原有任务或修改原始 CSV。

## 先理解四个入口

| 入口 | 用来做什么 | 会不会执行新回测 |
|---|---|---|
| 数据管理 | 下载、查看行情覆盖及可用标的 | 下载本身不会 |
| 策略回测 | 配一组参数，生成一份回测结果 | 会 |
| 任务历史 | 查看执行状态、结果、复制参数、比较任务 | 查看不会；复制后需自己提交 |
| 实验研究 | 查看同步后的研究档案、备注、比较、批量验证 | 比较不会；批量验证会 |

**任务**是执行记录，失败和取消也会留下记录。**实验**是成功回测同步到 MLflow 的档案。**批量验证**编排多个任务：前段比较候选，选好以后只在后段运行一个组合。Qlib 计算因子，MLflow 保存实验，现有系统负责行情、订单、费用、回测与页面。

本教程两种数据各有目的：

- **合成样例 `mvp_sample`**：可重复的功能检查，覆盖2024-01-02至2024-05-06，不是真实市场，不评价投资效果。
- **真实行情**：检查实际数据接入与交易规则。当前本机 `real` 基线覆盖2024-01-02至2025-12-31；具体以数据管理显示的覆盖为准。

## A．打开平台并确认环境

1. 打开 http://127.0.0.1:8765 。能打开就不要再启动一份服务。
2. 应看到「策略回测」「任务历史」「实验研究」「数据管理」四个标签，以及顶部使用教程。
3. 在策略下拉框确认以下四项：
   - 固定标的；
   - 横截面排名；
   - 动量择强（价格规则适配）；
   - Qlib 动量择强（独立因子引擎）。
4. 在「数据管理」查看已有数据、证券及覆盖说明。

**通过标准：**四个入口可切换，策略列表完整，合成样例及已准备的真实数据可选择。

如果页面打不开，在项目目录执行以下命令。已有服务时勿重复执行；端口被占用时先确认现有服务。

```sh
cd /Users/chenmao/Desktop/workspace/ai-instructure/04-applications/investment-research/a-stock-strategy
.venv/bin/python -m strategy serve --experiment-python reports/experiment-env/bin/python
```

当前机器已准备基础、MLflow、Qlib 三个环境，不需要为验收重装。若提示缺环境，分别参考 [实验环境说明](experiment-tracking.md) 和 [Qlib 环境说明](qlib-runtime.md)。不需要 DeepSeek 或其他 AI API Key。

## B．完成第一次固定标的回测

先选择策略和数据集，**最后再填写日期与参数**。切换策略/数据集可能重新设置表单，提交前核对一遍。

| 字段 | 填写值 |
|---|---|
| 策略 | 固定标的 |
| 历史数据集 | 合成样例 / `mvp_sample` |
| 标的 | `588000.SH` |
| 开始／结束日期 | `2024-01-02` / `2024-05-06` |
| 初始资金 | `100000` 元 |
| 持有交易日 | `1` |
| 最少下跌家数 | `4000` |
| 指数日收益 ≤（%） | `-1` |
| 佣金率（%） | `0.03` |
| 最低佣金 | `5` 元 |
| 滑点 | `2` 基点 |
| 同时进行策略有效性对照 | 暂不勾选 |

1. 点击「开始回测」。
2. 等待任务完成，记下任务编号。
3. 查看累计收益、最大回撤、胜率、交易次数、净值/回撤图及逐笔交易。
4. 展开「成交、取消与延后记录」及数据/模型说明。
5. 点击「导出结果 JSON」，保存到自己的验收文件夹，命名为 `B-固定标的.json`。
6. 等待显示「实验已同步」。同步发生在回测之后，可能稍晚。

**通过标准：**任务成功；这组合成样例应产生完整交易；JSON中的 `request` 对应填写值；交易日期符合收盘形成信号、下一交易日开盘执行的规则。未运行对照就不应凭空出现对照收益。

不要把“收益必须为正”当通过条件。出现预热、前一日指数价缺失等说明，要记录并理解它影响的是哪一天，而不是直接忽略全部警告。

**单位核对：**页面指数阈值 `-1%` 在 JSON 中是 `-0.01`；页面佣金 `0.03%` 是 `0.0003`；动量门槛后面使用小数输入，两者不同。

## E．验收三种选股/因子策略

以下三次均使用 B 的样例区间、资金、成本和市场触发条件，持有期统一为 `3`，不勾选有效性对照。候选列表选择 `588000.SH`、`510300.SH`、`159915.SZ`；多选时按住 Command（Mac）或 Ctrl。

### E1．横截面排名

选择「横截面排名」，候选为上述三只；窗口及权重保持页面默认值。运行后查看交易标的和导出的 `request.parameters`。

**通过标准：**任务可执行，参数被正确保存，成交标的只能来自候选列表。前期不足默认窗口时可能暂不选股，不等于任务失败；不要求三只都被买过。

### E2．本地动量规则

选择「动量择强（价格规则适配）」：

| 参数 | 值 |
|---|---|
| 候选 | 上述三只 ETF |
| 动量回看交易日 | `2` |
| 最低动量 | `-1` |
| 持有期 | `3` |

`-1` 表示最低动量为-100%，此处故意放宽门槛，以便功能验收产生交易，不是建议使用这个投资参数。运行、同步后命名为 `验收-E2-本地动量`。

**通过标准：**任务完成；请求保存窗口2、门槛-1；结果来源说明指向规则适配。此策略不应声称调用了 Qlib 因子运行时。

### E3．真正调用 Qlib

选择「Qlib 动量择强（独立因子引擎）」，使用 E2 完全相同的参数，提交前再次核对最低动量为 `-1`。

1. 运行时可能看到「Qlib 计算因子」阶段；阶段很快时可能来不及看到，不能只靠进度文字判断是否调用。
2. 完成后导出 JSON，命名为 `E3-Qlib.json`，同步后将实验命名为 `验收-E3-Qlib`。
3. 在导出的 JSON 中搜索 `factor_runtime`，检查：

| 字段 | 预期 |
|---|---|
| `metadata.factor_runtime.backend` | `qlib` |
| `version` | `0.9.7` |
| `expression` | `$close/Ref($close, 2)-1` |
| `input_sha256` / `output_sha256` | 存在且非空 |
| `rows` | 有逐日证券代码和score；预热不足时允许null |

**通过标准：**有实际运行元数据与因子结果，任务成功且可同步；不是只出现一个带 Qlib 名称的选项。

更深入时，到 `reports/workbench/runs/<任务完整编号>/qlib/` 查看 `input.csv`、`output.json`、`worker.log`。选一条非空score，在input中按统一日期序列找到该标的2个交易日前收盘价，计算 `当前价 / 过去价 - 1`，应在float32精度误差内接近score。不要要求文本小数完全相等。

在实验页比较 E2 和 E3：连续完整行情下结果应大体可解释；不能要求每笔完全一致——Qlib使用统一日历及float32，本地策略按标的行情行计算窗口，极近分数、门槛和数据缺口可能导致差别。

## F．验收二维参数网格与后段锁定

从 **`验收-E3-Qlib`** 这一条实验点击「批量验证」。不要随便从旧的零交易实验开始。

| 字段 | 首次验收填写 |
|---|---|
| 候选持有期 | `1,3` |
| 动量窗口 | `2,5` |
| 后段开始日 | `2024-03-01` |

1. 应提示 **4组前段回测 + 有合格候选时1次后段验证**。
2. 提交，观察前段筛选状态。
3. 前段应出现 `(持有1,窗口2)`、`(1,5)`、`(3,2)`、`(3,5)` 四个不同组合。
4. 四组成功后，在有完整交易的组里按累计收益最高选一组；同收益先选短持有期，再选短窗口。
5. 后段只应出现一行，它的**持有期和窗口都要与选中组合一致**。
6. 打开后段的「查看回测详情」，导出JSON核对 `request.holding_period_days`、`request.parameters.lookback` 与 `metadata.study.selected_candidate`。
7. 刷新浏览器，在批量历史中重新打开该批次，确认结果保留。

**通过标准：**四组不重复不遗漏；前后段日期不重叠；后段参数完整锁定；最多五个成员任务，不包含基础实验；旧批次仍可打开。若无完整交易，正确行为是“无合格候选”并且没有后段任务。

可选到MLflow按 `study_id` 找到该批次：正常完成时4个 `study_phase=selection` 和1个 `validation`；后段参数含完整 `study.selected_candidate`。

随后可用本地动量实验再试 `10,20,60` × `1,3,5` 的9组。窗口最多8个、持有期2–8个、每个1–252且不能重复，组合最多24组。固定标的实验不显示动量窗口；动量窗口留空沿用基础实验值。当前是两段验证，没有滚动验证或独立第三段最终测试。

**通过标准：**真实数据标识和来源正确、能完成回测、交易明细可查。不以盈利多少判定平台是否通过。不使用旧 `real_baidu` 数据作为上证指数基线。

### H2．新增贵州茅台并验证下载与回测解耦

1. 「数据管理 → 证券与行情」填写 `600519.SH`。可请求基线外日期；本项为验证完整回测，先选 `2024-01-02` 至 `2025-12-31`。

若在线数据源失败，保留错误提示，判为“下载链路未通过/受外部数据源阻塞”；继续用已有数据完成其他验收，不将其伪记为下载成功，也不认为全部平台失效。

## I．错误、无交易、取消与持久化

### I1．可预测的零交易

复制 B，最少下跌家数改为 `100000`，其余不变。完成后应无交易，页面说明没有完成交易，胜率显示无样本而不是策略胜率为零的有效结论。

再从该成功实验发起持有期 `1,3` 的批量验证，分界 `2024-03-01`：应为“无合格候选”，后段为空。

### I2．资金不足

H2有数据后，复制茅台任务，初始资金改为 `1000`。有触发信号时应看到 `INSUFFICIENT_CASH` 或买入资金不足说明、最小所需金额/取消记录。不能只给四个零指标而没有解释。

这属于回测成功但订单未成交，和程序运行失败是两种状态。如果区间完全无触发，应先调整到有信号的已验证区间，不能强行期待资金不足提示。

### I3．输入校验

在批量表单分别尝试，**不要同时改多个错误**：

| 输入 | 预期 |
|---|---|
| 持有期 `1,1` | 重复值拒绝 |
| 窗口 `0,20` 或 `1.5,20` | 范围/整数校验拒绝 |
| 持有期 `1,2,3,4`，窗口 `1,2,3,4,5,6,7` | 28组超过24，拒绝 |
| 后段开始日等于原开始日 | 无有效前段，拒绝 |
| 回测日期超出数据覆盖 | 表单或服务端明确拒绝 |

通过标准：没有提交半个批次，不产生一批明知不合法的成员任务。部分错误由浏览器原生校验提示，不一定有后端错误码。

### I4．取消任务与批次

发起一份 Qlib 网格，运行中点「取消批量验证」。应该停止编排并取消未完成成员，已经完成的成员仍可查看。取消后不应再新建后段任务；如果后段已在取消前启动，它应被取消而不是删掉记录。

也可对运行中的单次任务点「取消任务」。若任务已经完成得太快，按钮消失是正常情况，另用Qlib或固定标的对照任务测试。取消可能要等当前计算的检查点，观察最终状态，不要求点击瞬间全部停止。

### I5．刷新与重启

先刷新浏览器：任务、实验备注、批次结果都应保留。

可选服务重启：只在所有任务空闲时，在启动工作台的终端按 Ctrl+C，等退出，再按 A 的命令启动。若找不到启动终端，不要随意杀进程，先跳过并记录“重启未验收”。重新打开页面，检查 B、E3、F 的记录仍在。

运行中断的任务/批次不保证自动续跑，可能标记“已中断”，需要重新提交。不能把“自动续跑”写成当前验收要求。

Qlib环境缺失、因子超时和实验库故障已有后端保护，但本轮人工验收不要求你破坏环境、删除数据库或改坏行情来制造故障。遇到这些情况时分别记录 `QLIB_UNAVAILABLE`、`QLIB_FAILED` 或同步失败提示，并保留原任务。
