# 策略扩展接口

按用户已确认的单体分模块、逐步重构方向执行第一批：策略扩展。

当前 registry 提供构造器和表单，但工作台仍理解 symbol/candidate_symbols、weights 和排名策略窗口。新增策略因此需要修改业务编排。

目标：策略定义提供参数归一化、标的提取、预热需求和构造接口。参数 schema 继续驱动页面，公共数值校验独立；策略专属校验属于定义。工作台只验证数据覆盖、交易支持与任务通用参数，并调用定义执行。不改变两种现有策略算法、返回JSON、费用或数据合同。

采用显式 Python 注册；不增加运行时上传代码或第三方插件发现。相比只搬文件，该方案建立可验证的扩展接口；相比动态插件框架，保持部署与审计简单。

验证：注册第三种测试策略，使用不同标的参数名，经工作台运行无需新增分支；覆盖非法参数、默认值隔离、预热警告；固定及排名策略重构前后 metrics/equity/trades/events/execution_events/request 完全一致。全回归与代码审查后交付。数据服务、存储及 CLI 统一属于后续独立批次。
