# 策略解释与决策审计

用户已批准上一轮提出的规则卡、逐日决策、交易时间线建设。本轮沿用该范围，不增加策略或改变成交模型。

方案比较：仅增加文字说明成本低但不能解释具体交易；事后重算解释易与执行偏离且重复计算；采用运行时留痕，确保解释与选择使用同一计算结果。

## 合同
- 动量两策略提供 evaluate(as_of, market, universe)，返回 selection 与 candidates。select 复用 evaluate，不另写一套排序。候选记录 symbol、score、reference_date、reference_close、current_close、status、reason。已知数据/交易状态不合格有明确原因；同分证券代码升序。
- 引擎仅在原本允许择股的日子调用该评估。每日 decision_events 记录市场条件、持仓阻断、selected_symbol、计划入场、候选及状态。未触发或持仓时候选不计算并明确显示，不制造假想订单。
- 执行事件追加 signal_date、entry_date、planned_exit_date，串联订单与原始信号。退出日期沿用现有引擎的买入日索引+持有期；超出样本记未知，不虚构未来日历。
- 固定和横截面保留通用市场与执行解释；本轮逐候选分数原因仅支持本地与 Qlib 动量，其他策略明确提示范围。
- 页面新增独立 explanations.js：动态参数规则卡、结果逐日选择器和候选表、执行时间线。旧结果没有 decision_events 时提示重跑，不伪造历史决策。文案强调单持仓、无止盈止损、不因排名变化换仓，Qlib只是计算引擎。
- 不增加网络/AI/MLflow依赖，不改历史结果，结果 JSON 与 MLflow artifact 自然包含解释。批量任务同样记录，随机对照不增候选计算。

## 验证
先写决策因果、同分、候选缺失、阈值、持仓阻断、计划与实际日期、旧结果兼容的失败测试；实现后跑现有交易测试保障收益不变。前端用节点测试与浏览器样例回测检查动态更新、候选表、旧结果提示与窄屏。
