# 实验记录与比较

网页工作台现已接入 MLflow。成功回测自动同步参数、策略版本、行情/源码哈希、收益指标及完整结果；Qlib 已有可选的隔离因子计算入口（见 [Qlib 因子引擎](qlib-runtime.md)），成交仍由原引擎完成；RQAlpha 未接入。

## 启动

在项目目录创建独立环境（本机已安装）：

```bash
uv venv --python 3.11 reports/experiment-env
uv pip install --python reports/experiment-env/bin/python 'mlflow==3.16.0'
```

启动工作台，解释器参数会在启动时转为绝对路径：

```bash
.venv/bin/python -m strategy serve --experiment-python reports/experiment-env/bin/python
```

另开终端，在同一项目目录启动实验页面：

```bash
reports/experiment-env/bin/python -m mlflow server \
  --host 127.0.0.1 --port 5000 --workers 1 \
  --backend-store-uri "sqlite:///$(pwd)/reports/workbench/mlflow.sqlite3"
```

工作台为 http://127.0.0.1:8765，实验页面为 http://127.0.0.1:5000。若修改 MLflow 页面端口，工作台同时传 `--experiment-ui-url http://127.0.0.1:新端口`。不传 `--experiment-python` 时实验同步关闭，正常回测可继续使用。

## 中文实验研究页（常用入口）

无需学习英文 MLflow 页面。打开工作台的「实验研究」标签页，展开「跟着做一次 · 比较持有 1、3、5 天」即可查看页内说明。

1. 在「策略回测」运行实验，等待结果页显示「实验已同步」。旧任务可以到「任务历史」点击「同步到实验库」，无需重新回测。
2. 打开「实验研究」，按名称、备注、标的或策略筛选。默认名称包含中文策略、标的和持有天数；合成数据明确显示「合成样例」。列表保留核心指标，基准及随机对照在勾选比较后展示。
3. 勾选 2 至 4 条实验，查看收益、回撤、胜率、交易笔数和参数变化。区间、数据、资金、费用或源码版本不同时显示提示；版本缺失也会说明，不能据此确认实验可比。
4. 点击「编辑」保存名称和备注，例如“持有3日——观察回撤变化”。名称最多120字，备注最多2000字；保存到 MLflow，刷新和重启后保留。
5. 点击「复制重跑」，原参数会带回回测表单，修改后创建新任务；原实验保留。点击「查看详情」查看完整净值及逐笔交易。

买入持有是一直持有标的的对照；随机择时是随机安排买入时点的对照。未运行或未保存的对照显示“—”，不是0%；无完整交易时胜率也显示“—”。要生成对照，在固定标的策略中勾选「同时进行策略有效性对照」。

名称、备注、指标来自 MLflow；任务参数来自对应本机冻结请求。页面按需加载，不在后台不断重查全库。当前检索最近200条完成的MLflow记录，再保留关联本机成功任务的记录；新任务同步后点击「刷新实验」。

「高级工具」默认收起，仍可打开原始 MLflow 页面。中文名称备注保存在 `workbench.annotation` 标签中，不修改原始回测参数。`result.json` artifact 包含完整净值、交易、警告、对照结果和逐文件哈希。源码快照用于审计，实际执行仍使用服务启动时加载的模块。

## 批量选参与后段验证

单次任务回答“一组参数跑出来怎样”；批量验证把多组参数放在同一前段比较，再锁定一个候选去运行后段。

1. 在「实验研究」的一条已同步成功实验上点击「批量验证」。
2. 填写候选持有期，例如 `1,3,5`（2–8 个不重复整数，范围 1–252），并填写「后段开始日」。其他策略、标的、资金和成本参数沿用原实验。

3. 点击「开始批量验证」。系统在前段运行全部候选，仅在有完整交易的候选中按累计收益最高选取；相同收益先选较短持有期，再选较短动量窗口。规则固定，不读取后段收益选参。
4. 查看分开的前段比较表和后段验证表。后段只运行锁定的一组参数，可打开各成员回测详情。刷新页面后批次历史保留。

本地动量和 Qlib 动量实验还可填写「动量窗口」，例如 `10,20,60`，与 `1,3,5` 持有期组合为 9 组。窗口支持 1–8 个不重复整数（1–252），总组合最多24组；留空沿用原值。后段仅执行选定的完整组合，其他策略不支持窗口网格。Qlib 各成员独立计算因子，没有跨任务缓存。

分界日映射为该日或之后的首个交易日，两段各需至少两个交易日。各段重新使用初始资金，不继承前段持仓；本批量关闭 100 轮随机对照。候选全部无完整交易时不运行后段；候选失败则结束批次并取消未完成成员。取消批次保留已有结果；服务中断后批次显示中断，不自动续跑。

同批成员复用原任务的冻结行情，并在创建批次时统一捕获源码供审计，实际执行使用当前服务加载的代码。MLflow 的 `study_id`、`study_phase` 标签关联成员，后段参数记录选中的持有期。批次状态与输入保存在 `reports/workbench/studies/`。

“被选中”只表示前段按固定规则排名最高，可能仍然亏损。若此前已查看后段结果，或反复用它修改参数，它就不再是严格的未见数据验证。页面中的合成样例用于演示流程，不能作为真实市场盈利证据。

## 模块与恢复

- `application/research.py` / `storage/mlflow_research.py`：中文实验查询和名称备注编辑，SDK在独立子进程运行。
- `application/studies.py` / `interfaces/web/static/studies.js`：批量任务编排、选参锁定、后段验证和历史页面，复用现有回测引擎。
- `interfaces/web/static/research.js`：中文列表、筛选、编辑、比较和使用说明入口。
- `application/experiments.py`：独立同步队列、原子状态文件、错误隔离与重试。
- `storage/mlflow_export.py`：在配置的解释器中运行 MLflow SDK，显式写参数、指标和结果。
- `application/jobs.py`：回测成功落库后入队，原有计算线程不等待 MLflow。
- `GET /api/experiments`：功能开关与本机页面地址。
- `POST /api/jobs/{id}/experiment`：成功任务补录/重试，重复请求复用同一个 run。

数据库、同步状态及 artifacts 位于 `reports/workbench/`，备份时应整体保留。独立环境位于 `reports/experiment-env/`，可重新安装。不要只复制 MLflow 数据库而丢弃 artifacts。

关闭服务会等待当前同步子进程（超时 60 秒），未开始的同步保留 pending，下次启动恢复。崩溃发生在成功落库与同步入队之间时，可在历史任务中手动补录。单用户单实例部署，不支持多个工作台进程同时写同一个状态目录。MLflow 页面可以关闭，后台同步直接写本机存储，不依赖页面服务在线。

本轮只自动接入网页工作台任务；旧式 CLI `backtest` 不自动记录。没有自动接 AI、策略搜索或模型训练。

## 验证

相关 Python 测试覆盖队列去重、失败重试、重启恢复、状态文件损坏、状态写入失败、回测独立性和原有任务/HTTP合同。前端测试覆盖状态、入口、重试与轮询。

真实 MLflow 验收已校验：成功任务对应 FINISHED run，参数和数值指标一致，完整 artifact 可读取，重复同步仅一条 run。
