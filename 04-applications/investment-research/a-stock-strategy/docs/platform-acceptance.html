先理解四个入口

入口 用来做什么 会不会执行新回测
数据管理 下载、查看行情覆盖及可用标的 下载本身不会
策略回测 配一组参数，生成一份回测结果 会
任务历史 查看执行状态、结果、复制参数、比较任务 查看不会；复制后需自己提交
实验研究 查看同步后的研究档案、备注、比较、批量验证 比较不会；批量验证会

任务是执行记录，失败和取消也会留下记录。实验是成功回测同步到 MLflow 的档案。批量验证编排多个任务：前段比较候选，选好以后只在后段运行一个组合。Qlib 计算因子，MLflow 保存实验，现有系统负责行情、订单、费用、回测与页面。

本教程两种数据各有目的：

  • 合成样例 mvp_sample：可重复的功能检查，覆盖2024-01-02至2024-05-06，不是真实市场，不评价投资效果。
  • 真实行情：检查实际数据接入与交易规则。当前本机 real 基线覆盖2024-01-02至2025-12-31；具体以数据管理显示的覆盖为准。
建议双窗口操作：左边打开本教程，右边打开工作台。先选策略与数据，再填参数；每章完成后保存任务编号。本文件不会执行回测，也不会连接 AI 服务。

先把四个概念分清

Qlib 负责计算动量因子；回测引擎 根据市场触发条件和因子选择证券，模拟订单与费用；MLflow 保存成功实验；批量验证 先在前段选参数，再锁定参数跑一次后段。

动态择强并不是每天下单：只有市场条件触发、当前持仓及执行规则允许时，才从候选中选择符合门槛的证券。候选池也不意味着同时持有全部股票。

**单位核对：**页面指数阈值 -1% 在 JSON 中是 -0.01；页面佣金 0.03% 是 0.0003；动量门槛后面使用小数输入，两者不同。

E．验收三种选股/因子策略

以下三次均使用 B 的样例区间、资金、成本和市场触发条件，持有期统一为 3，不勾选有效性对照。候选列表选择 588000.SH、510300.SH、159915.SZ；多选时按住 Command（Mac）或 Ctrl。

E1．横截面排名

选择「横截面排名」，候选为上述三只；窗口及权重保持页面默认值。运行后查看交易标的和导出的 request.parameters。

**通过标准：**任务可执行，参数被正确保存，成交标的只能来自候选列表。前期不足默认窗口时可能暂不选股，不等于任务失败；不要求三只都被买过。

E2．本地动量规则

选择「动量择强（价格规则适配）」：

参数 值
候选 上述三只 ETF
动量回看交易日 2
最低动量 -1
持有期 3

-1 表示最低动量为-100%，此处故意放宽门槛，以便功能验收产生交易，不是建议使用这个投资参数。运行、同步后命名为 验收-E2-本地动量。

**通过标准：**任务完成；请求保存窗口2、门槛-1；结果来源说明指向规则适配。此策略不应声称调用了 Qlib 因子运行时。

E3．真正调用 Qlib

选择「Qlib 动量择强（独立因子引擎）」，使用 E2 完全相同的参数，提交前再次核对最低动量为 -1。

  1. 运行时可能看到「Qlib 计算因子」阶段；阶段很快时可能来不及看到，不能只靠进度文字判断是否调用。
  2. 完成后导出 JSON，命名为 E3-Qlib.json，同步后将实验命名为 验收-E3-Qlib。
  3. 在导出的 JSON 中搜索 factor_runtime，检查：
字段 预期
metadata.factor_runtime.backend qlib
version 0.9.7
expression $close/Ref($close, 2)-1
input_sha256 / output_sha256 存在且非空
rows 有逐日证券代码和score；预热不足时允许null

**通过标准：**有实际运行元数据与因子结果，任务成功且可同步；不是只出现一个带 Qlib 名称的选项。

更深入时，到 reports/workbench/runs/<任务完整编号>/qlib/ 查看 input.csv、output.json、worker.log。选一条非空score，在input中按统一日期序列找到该标的2个交易日前收盘价，计算 当前价 / 过去价 - 1，应在float32精度误差内接近score。不要要求文本小数完全相等。

在实验页比较 E2 和 E3：连续完整行情下结果应大体可解释；不能要求每笔完全一致——Qlib使用统一日历及float32，本地策略按标的行情行计算窗口，极近分数、门槛和数据缺口可能导致差别。

G．验收“盈利是不是因为标的上涨”的对照功能

  1. 复制 B 固定标的任务的参数，勾选「同时进行策略有效性对照」。
  2. 运行后查看买入持有对照、100轮随机择时及相应分布/比较。
  3. 与 B 相比，原策略参数没有变化，原策略收益不应仅因勾选对照而改变。
  4. 保存此任务，命名为 验收-G-有效性对照。

**通过标准：**对照真实产生而非显示缺省零；原策略结果保持一致；运行中有对照进度。对照更慢是预期，但不应无限停住。

该功能目前仅支持固定标的。动量、横截面及批量网格没有自动运行100轮随机对照；那里显示“—”不等于0%。

H．从真实行情到新增股票

H1．先验证已有真实ETF数据

在「数据管理」确认真实数据集包含上述ETF和广度覆盖。新建固定标的回测：

  • 数据集选择真实基线 real，不是合成样例；
  • 标的 588000.SH；
  • 区间 2024-03-01 至 2025-12-31（仅在实际覆盖包含该区间时）；
  • 资金100000，持有期3，其余沿用 B；不勾选对照。

**通过标准：**真实数据标识和来源正确、能完成回测、交易明细可查。不以盈利多少判定平台是否通过。不使用旧 real_baidu 数据作为上证指数基线。

H2．新增贵州茅台并验证下载与回测解耦

  1. 「数据管理」填写 600519.SH；下载日期选择在页面显示的市场广度基线以内，例如 2024-01-02 至 2025-12-31。
  2. 点击「新增代码并下载行情」。即使曾下载过，也应产生新的独立数据版本。
  3. 等待下载结果，记录数据集编号，点击「查看此数据集」核对名称、代码、覆盖、来源与可回测状态。
  4. 下载完成后，任务历史不应凭空多出一条回测。
  5. 去「策略回测」，选择固定标的，基线选择 real，保持「跨版本选择研究证券（真实行情）」勾选。选择 600519.SH，在该证券的来源版本中选择刚下载的版本。按共同可用区间填写日期，资金设 1000000，持有期3，其余同 B，运行。
  6. 查看股票的100股整手、佣金、过户费、卖出印花税记录与模型说明。

**通过标准：**下载成功产生独立数据版本；新标的能在该版本中选择并回测；旧数据和结果保留；股票费用按当前日期规则处理。金额受近似成交价影响，不把前复权价当真实历史成交价。

若在线数据源失败，保留错误提示，判为“下载链路未通过/受外部数据源阻塞”；继续用已有数据完成其他验收，不将其伪记为下载成功，也不认为全部平台失效。

I．错误、无交易、取消与持久化

I1．可预测的零交易

复制 B，最少下跌家数改为 100000，其余不变。完成后应无交易，页面说明没有完成交易，胜率显示无样本而不是策略胜率为零的有效结论。

再从该成功实验发起持有期 1,3 的批量验证，分界 2024-03-01：应为“无合格候选”，后段为空。

I2．资金不足

H2有数据后，复制茅台任务，初始资金改为 1000。有触发信号时应看到 INSUFFICIENT_CASH 或买入资金不足说明、最小所需金额/取消记录。不能只给四个零指标而没有解释。

这属于回测成功但订单未成交，和程序运行失败是两种状态。如果区间完全无触发，应先调整到有信号的已验证区间，不能强行期待资金不足提示。

I3．输入校验

在批量表单分别尝试，不要同时改多个错误：

输入 预期
持有期 1,1 重复值拒绝
窗口 0,20 或 1.5,20 范围/整数校验拒绝
持有期 1,2,3,4，窗口 1,2,3,4,5,6,7 28组超过24，拒绝
后段开始日等于原开始日 无有效前段，拒绝
回测日期超出数据覆盖 表单或服务端明确拒绝

通过标准：没有提交半个批次，不产生一批明知不合法的成员任务。部分错误由浏览器原生校验提示，不一定有后端错误码。

I4．取消任务与批次

发起一份 Qlib 网格，运行中点「取消批量验证」。应该停止编排并取消未完成成员，已经完成的成员仍可查看。取消后不应再新建后段任务；如果后段已在取消前启动，它应被取消而不是删掉记录。

也可对运行中的单次任务点「取消任务」。若任务已经完成得太快，按钮消失是正常情况，另用Qlib或固定标的对照任务测试。取消可能要等当前计算的检查点，观察最终状态，不要求点击瞬间全部停止。

I5．刷新与重启

先刷新浏览器：任务、实验备注、批次结果都应保留。

可选服务重启：只在所有任务空闲时，在启动工作台的终端按 Ctrl+C，等退出，再按 A 的命令启动。若找不到启动终端，不要随意杀进程，先跳过并记录“重启未验收”。重新打开页面，检查 B、E3、F 的记录仍在。

运行中断的任务/批次不保证自动续跑，可能标记“已中断”，需要重新提交。不能把“自动续跑”写成当前验收要求。

Qlib环境缺失、因子超时和实验库故障已有后端保护，但本轮人工验收不要求你破坏环境、删除数据库或改坏行情来制造故障。遇到这些情况时分别记录 QLIB_UNAVAILABLE、QLIB_FAILED 或同步失败提示，并保留原任务。
